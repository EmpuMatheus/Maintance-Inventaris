# OFFICE INVENTORY MAINTENANCE SYSTEM

## Product Requirements Document (PRD)

**Project Name:** Office Inventory Maintenance System
**Version:** 1.0
**Primary User:** Tim IT
**Platform:** Web Application
**Primary Focus:** Monitoring kondisi dan maintenance seluruh inventaris kantor

---

# 1. Project Overview

Office Inventory Maintenance System adalah aplikasi berbasis web yang digunakan oleh Tim IT untuk mengelola, memonitor, dan mencatat kondisi seluruh inventaris kantor.

Sistem tidak hanya berfungsi sebagai daftar aset, tetapi sebagai pusat informasi lifecycle inventaris mulai dari:

**Registrasi Aset → Penempatan → Penggunaan → Monitoring Kondisi → Pelaporan Kerusakan → Maintenance → Riwayat → Disposal**

Setiap aset memiliki identitas unik dan QR Code sehingga Tim IT dapat membuka informasi aset dengan cepat menggunakan smartphone.

---

# 2. Objectives

Tujuan utama sistem:

1. Mengetahui seluruh inventaris yang dimiliki perusahaan.
2. Mengetahui lokasi setiap aset.
3. Mengetahui siapa pengguna/PIC aset.
4. Mengetahui kondisi aset terkini.
5. Mengetahui aset yang sedang rusak.
6. Mengetahui aset yang sedang maintenance.
7. Menyimpan histori maintenance.
8. Menyimpan histori perpindahan aset.
9. Mengontrol jadwal preventive maintenance.
10. Menganalisis biaya maintenance.
11. Mempermudah audit inventaris.
12. Mengurangi kehilangan informasi mengenai aset.
13. Mempermudah Tim IT melakukan pengecekan melalui QR Code.

# 8. Asset Condition

Kondisi aset:

### GOOD

Aset bekerja normal dan tidak memiliki masalah.

### FAIR

Aset masih dapat digunakan tetapi memiliki indikasi penurunan kondisi.

### NEED ATTENTION

Aset membutuhkan pengecekan atau maintenance.

### BROKEN

Aset tidak dapat digunakan secara normal.

### CRITICAL

Kerusakan berat atau membutuhkan tindakan segera.

### RETIRED

Aset sudah tidak direkomendasikan untuk digunakan.

---

Monitoring kondisi merupakan fitur utama aplikasi.

Contoh:

`GOOD → FAIR → NEED ATTENTION → MAINTENANCE → GOOD`

History menyimpan:

* Previous Condition
* New Condition
* Changed By
* Date
* Reason
* Notes
* Attachment

Dengan demikian kondisi aset tidak hanya menunjukkan kondisi saat ini tetapi juga perjalanan kondisi aset.

Range:

`0 - 100`

Contoh:

| Score  | Condition |
| ------ | --------- |
| 90–100 | Excellent |
| 75–89  | Good      |
| 60–74  | Fair      |
| 40–59  | Poor      |
| 0–39   | Critical  |

Health Score dapat dihitung berdasarkan:

* Umur aset
* Jumlah kerusakan
* Frekuensi maintenance
* Severity kerusakan
* Waktu penggunaan
* Maintenance terakhir

Fitur ini dapat dikembangkan pada fase lanjutan.

Sistem harus menjawab pertanyaan berikut dalam beberapa detik:

**Barang ini apa?**

**Barang ini ada di mana?**

**Siapa yang menggunakan?**

**Bagaimana kondisinya?**

**Pernah rusak apa saja?**

**Kapan terakhir maintenance?**

**Kapan harus maintenance lagi?**

**Berapa biaya yang sudah dikeluarkan?**

**Apakah masih layak dipakai?**

Jika informasi tersebut dapat ditemukan dengan cepat, maka sistem telah memenuhi tujuan utamanya.
