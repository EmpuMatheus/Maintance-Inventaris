# DATABASE.md

# Office Inventory Maintenance System

**Database:** PostgreSQL
**Version:** 1.0
**Primary Application:** Office Inventory Maintenance System
**Primary User:** IT Team

---

# 1. Database Objectives

Database dirancang untuk menangani seluruh lifecycle inventaris kantor:

`Asset Registration`

↓

`Assignment`

↓

`Condition Monitoring`

↓

`Issue Reporting`

↓

`Maintenance`

↓

`Movement`

↓

`History`

↓

`Retirement / Disposal`

Prinsip utama database:

* Data aset tidak boleh kehilangan history.
* Perubahan kondisi harus tercatat.
* Perpindahan aset harus tercatat.
* Maintenance harus memiliki history.
* Setiap aktivitas penting memiliki audit log.
* Master data menggunakan relational reference.
* Data penting tidak dihapus secara permanen.
* Struktur harus mudah dikembangkan.

`snake_case`

```text
asset_categories

```

Primary Key:

```text
id
```

Foreign Key:

```text

```

Timestamp:

```text
created_at
updated_at
deleted_at
```

---

# 3. Recommended ID Strategy

Gunakan UUID sebagai internal database ID.

Contoh:

```text
id UUID PRIMARY KEY
```

Sedangkan kode yang dilihat user menggunakan readable code.

Contoh:

```text
AST-IT-000001
MNT-2026-000001
TKT-2026-000001
MOV-2026-000001
```

Dengan demikian:

```text
UUID
```

digunakan sistem.

Sedangkan:

```text
asset_code
maintenance_code
ticket_code
```

digunakan user.

# 42. SOFT DELETE

Data penting sebaiknya tidak menggunakan hard delete.

Gunakan:

```text

```

Contoh:

```text
deleted_at = NULL
```

berarti aktif.

Jika:

```text
deleted_at = 2026-07-30 10:30:00
```

berarti sudah dihapus secara logical.

Terutama untuk:

```text
assets
users
vendors
```

# 45. REPEATED FAILURE

Repeated failure tidak memerlukan table khusus.

Dapat dihitung dari:

```text

```

```text

```

dan:

```text
COUNT >= 3
```

```text

```

```text
REPEATED_FAILURE = TRUE
```

# 58. DATA INTEGRITY PRINCIPLE

Database harus mengikuti prinsip:

```text
CURRENT STATE
+
HISTORY
```

Contoh:

Current condition:

```text
assets.condition
```

History:

```text
asset_condition_history
```

Current location:

```text
assets.room_id
```

History:

```text
asset_movements
```

Current PIC:

```text
assets.current_pic_id
```

History:

```text
asset_assignments
```

Dengan pola ini aplikasi tetap cepat ketika membaca kondisi sekarang tanpa kehilangan histori.
