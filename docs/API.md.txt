# API.md

# Office Inventory Maintenance System

**Version:** 1.0
**API Style:** REST API
**Backend:** Node.js + Express.js + TypeScript
**Database:** PostgreSQL
**Authentication:** JWT
**Validation:** Zod
**Content Type:** `application/json`

---

# 1. API Objectives

API menjadi communication layer antara:

```text
React Frontend
      ↓
   REST API
      ↓
Business Logic
      ↓
 PostgreSQL
```

API bertanggung jawab terhadap:

* Authentication
* Authorization
* Input validation
* Business logic
* Database transaction
* Asset management
* Condition monitoring
* QR lookup
* Maintenance
* Ticket
* Asset movement
* Master data
* Reporting
* Audit logging
* Notification

Frontend tidak boleh mengakses database secara langsung.

---

```text

```

# 3. API Principles

API harus mengikuti prinsip:

```text
CONSISTENT
PREDICTABLE
SECURE
VALIDATED
VERSIONED
DOCUMENTED
```

Frontend tidak boleh membutuhkan pengetahuan tentang struktur internal database.

Contoh:

Jangan expose query database melalui frontend.

Frontend:

```text
GET /api/v1/assets?condition=BROKEN
```

Bukan:

```text
SELECT * FROM assets WHERE condition = 'BROKEN'
```

```http

```

Contoh:

```json
{
  "assetName": "Lenovo ThinkPad E14",

  "brandId": "uuid"
```

```http
Content-Type: multipart/form-data
```

---

# 5. Response Format

Semua response menggunakan format konsisten.

Success:

```json
{
  "success": true,
  "data": {}
}
```

Success dengan message:

```json
{
  "success": true,
  "message": "Asset created successfully.",
  "data": {}
}
```

Error:

```json
{
  "success": false,
  "error": {
    "code": "ASSET_NOT_FOUND",
    "message": "Asset not found."
  }
}
```

---

# 6. Validation Error

Contoh:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid request data.",
    "fields": {
      "assetName": [
        "Asset name is required."
      ],
      "categoryId": [
        "Invalid category."
      ]
    }
  }
}
```

Frontend dapat langsung memetakan:

```text
fields
```

ke React Hook Form.

---

# 7. HTTP Status Codes

Gunakan standard:

```text
200 OK
Request berhasil

201 Created
Resource berhasil dibuat

204 No Content
Request berhasil tanpa response body

400 Bad Request
Invalid request

401 Unauthorized
Belum login / token invalid

403 Forbidden
Tidak memiliki permission

404 Not Found
Resource tidak ditemukan

409 Conflict
Duplicate / conflicting state

422 Unprocessable Entity
Validation / business rule failure

429 Too Many Requests
Rate limit

500 Internal Server Error
Unexpected server error
```

# 11. Logout

Jika menggunakan refresh-token/session strategy:

```http
POST /api/v1/auth/logout
```

Server harus menghapus atau revoke session/refresh token terkait.

Access token yang stateless dan belum expired tidak dianggap revoked kecuali sistem memiliki token blacklist/session store.

# 14. Permission Enforcement

Permission harus diperiksa pada backend.

# 57. Maintenance Workflow Rules

Recommended:

```text
OPEN
 ↓
ASSIGNED
 ↓
IN_PROGRESS
 ├── WAITING_PART
 │       ↓
 │   IN_PROGRESS
 │
 ↓
TESTING
 ↓
COMPLETED
```

`CANCELLED` hanya diperbolehkan dari state tertentu sesuai business rule.

Invalid transition:

```json
{
  "success": false,
  "error": {
    "code": "INVALID_MAINTENANCE_TRANSITION",
    "message": "Maintenance cannot move from COMPLETED to IN_PROGRESS."
  }
}
```
